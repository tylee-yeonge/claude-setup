# 계획 파일(plan.md) 작성 템플릿

`~/.claude/rules/docs-structure.md`의 spec 골격의 원형이 되는 템플릿. 문서의 위치/파일명/spec-plan 분리는 docs-structure.md가 우선하며, 이 문서는 § 구조의 상세(롤백 전략 옵션 비교 표, 진행 보드, semver/CHANGELOG 결정 등)가 필요할 때 spec 작성에 차용하는 참고 자료다.

참고 사례: `/Volumes/TYLEE_256/nanobot-docker/nanobot-0.2.0-migration-plan.md` (이 템플릿의 모델이 된 문서).

## 작성 원칙

- **언어**: 한국어 (전역 룰 준수). 코드 블록 / 식별자 / 커밋 메시지는 영어.
- **이모지 금지**: 섹션 헤더, 체크박스, 본문 어디에도 사용 안 함.
- **섹션 번호**: `§0`, `§1` 형태로 부여하고 다른 섹션에서 참조할 때 `§2.3 참고` 식으로 인용한다.
- **체크박스**: TODO/검증 항목은 `- [ ]` / `- [x]` 로 표기. 완료 상태가 단일 진실 공급원이 되도록 §5 진행 보드와 §6 검증 체크리스트의 항목을 분리한다.
- **테이블 활용**: 옵션 비교 / 결정 사항 / 항목별 영향 분석은 마크다운 테이블로 표현. ASCII 박스 드로잉 금지.
- **다이어그램**: 흐름도가 필요하면 Mermaid 사용.
- **외과적 변경 원칙 반영**: "변경 없음"인 파일도 §3 결정 사항 표와 부록에 명시한다 — 검토되지 않은 채 누락된 게 아니라 의도적으로 보존된 영역임을 드러내기 위함.
- **의사결정의 옵션 비교**: 채택 / 비채택 옵션을 모두 적고 사유를 남긴다. "왜 이게 아닌가"를 함께 적어야 미래의 자신이 같은 분기점을 다시 고민하지 않는다.
- **불확실성 명시**: "이 마이그레이션이 hang을 fix한다는 보장은 없음" 같이 한계를 §0 또는 §8에 별도 섹션으로 적는다. 단정하지 않는다.
- **롤백 전략**: 되돌릴 수 없는 작업이면 §7에 롤백 옵션을 옵션 비교 표 형태로 적는다.
- **현재 상태 기준 작성 (diff 금지)**: 기존 plan.md를 보완·갱신할 때도 "현재 무엇을 제안하는가"만 담는 현재 상태 문서로 쓴다. 변경 이력은 본문에 적지 않는다. 이는 모든 마크다운 문서에 적용되는 일반 원칙이며 상세는 `~/.claude/rules/markdown.md`의 "현재 상태 기준 작성" 항목을 따른다. (이 문서 한정 예외: §8 의사결정 로그의 "비채택 옵션"은 변경 이력이 아니라 현재 결정의 근거이므로 그대로 유지한다.)

## 표준 골격 (스켈레톤)

작업 성격에 따라 일부 섹션은 생략 가능하다. 단, 생략하더라도 §0 배경 / §3 결정 사항 / §4 구현 단계 / §5 진행 보드는 거의 항상 필요하다.

```markdown
# {{작업 제목}} 설계 ({{버전 또는 식별자}})

> 작성일: YYYY-MM-DD
> 대상: {{변경 대상 파일 / 모듈 / 시스템}}
> 사유: {{한 줄 요약 — 왜 이 작업이 필요한가}}
> 부수 효과: {{기대되는 부수 효과. 보장이 아닌 기대라면 그 점을 명시 + 관련 § 참조}}

## 섹션 채택 가이드

| 작업 성격 | 필수 섹션 | 생략 가능 |
|---|---|---|
| 외부 의존성 업그레이드 / 마이그레이션 | §0 ~ §8 전부 + 부록 | — |
| 신규 기능 추가 | §0, §1(설계), §2(영향), §3, §4, §5, §6, 부록 | §7(되돌리기 쉬우면), §8(옵션이 단일하면) |
| 리팩토링 | §0, §2, §3, §4, §5, §6 | §1, §7(이전 commit으로 되돌리면 충분 시), §8 |
| 버그 수정 (단발) | §0(재현 + 원인), §4(수정 + 테스트), §6(검증) | 나머지 |

작업이 단발 버그 수정 수준이면 별도 plan.md를 만들지 않고 대화 안에서 처리해도 된다 — CLAUDE.md의 "복잡한 작업"에 해당할 때만 이 템플릿을 사용한다.

## 파일 위치 관례

- 위치와 파일명은 `~/.claude/rules/docs-structure.md`를 따른다 (spec: `docs/superpowers/specs/YYYY-MM-DD-<topic>-design.md`).
- 개인 메모 성격의 문서는 `~/.claude/plans/`에 같은 파일명 규칙으로 저장 가능.
