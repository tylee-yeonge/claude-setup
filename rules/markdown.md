# Markdown 작성 규칙

## Bold/Italic 인접 한글 렌더링 문제

CommonMark 스펙상 닫는 `**`/`*`는 **right-flanking delimiter run**일 때만 emphasis로 인식된다. 다음 조건을 모두 만족해야 한다:

1. 앞이 공백이 아닐 것
2. (a) 앞이 구두점이 아니거나, (b) 앞이 구두점이면 뒤가 공백/구두점일 것

한글(Hangul syllable)은 Unicode 카테고리상 letter(Lo)라 구두점도 공백도 아니다. 따라서 **닫는 `**`/`*` 바로 앞이 구두점(`)`, `.`, `!`, `?`, `,`, `]` 등)이고 뒤가 한글이면 emphasis가 풀려 asterisk가 그대로 노출된다.**

VS Code 미리보기(markdown-it), GitHub, GitLab 모두 CommonMark를 따르므로 동일 증상이 나타난다.

### 깨지는 패턴 예시

| 입력 | 의도 | 실제 렌더링 |
|------|------|-------------|
| `**용어(영문명)**를` | **용어(영문명)** 를 | `**용어(영문명)**를` (raw) |
| `**Quantization)**는` | **Quantization)** 는 | `**Quantization)**는` (raw) |

### 권장 수정: 구두점을 bold 밖으로

핵심 용어만 굵게 처리하고, 부가 정보(영문 풀네임, 약자 등)는 일반 텍스트로 둔다. 한글 조사는 영문/숫자/letter에 붙으면 정상 동작한다.

- `**IoU(Intersection over Union)**를` → `**IoU**(Intersection over Union)를`
- `**양자화(Quantization)**는` → `**양자화**(Quantization)는`
- `**엔진(.trt 파일)**을` → `**엔진**(.trt 파일)을`

여러 용어를 한 번에 굵게 한 경우는 분리:
- `**A(X)와 B(Y)**를` → `**A**(X)와 **B**(Y)를`

이 규칙은 italic(`*...*`)에도 동일하게 적용된다.

### 정상 동작하는 패턴 (수정 불필요)

닫는 `**` 앞이 letter(한글/영문/숫자)면 right-flanking 조건이 성립한다.

- `**도구**를` (한글 letter + 한글)
- `**FP**다` (영문 letter + 한글)
- `**YOLO11**이다` (숫자 + 한글)
- `**Backbone(백본)**:` (구두점 + 구두점 → 2b 조건 성립)

## 숫자/날짜 범위

`~` 대신 `-` 사용. `~`는 마크다운 일부 렌더러(특히 GFM 확장)에서 취소선(`~~text~~`)으로 오인식될 수 있다.

- 잘못: `2018~2024`, `100~200ms`
- 옳음: `2018-2024`, `100-200ms`

## CJK 문자 너비와 ASCII 박스

한글은 모노스페이스 폰트에서 2칸을 차지한다. ASCII 박스(`+---+`, `|...|`)로 정렬해야 할 경우 한글이 섞이면 오른쪽 경계가 어긋난다. **박스 대신 마크다운 표(`| ... |`)를 우선 사용한다.** 표는 렌더러가 셀 폭을 자동 조정한다.
